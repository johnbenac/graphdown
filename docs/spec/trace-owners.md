# Trace ownership map

Use this as the “who owns what” index when tagging or auditing tests. Keep requirement prefixes aligned to the folders where the production logic lives and the primary suites that should carry the tags.

| Prefixes | Owning subsystem | Production code (primary) | Tests/checks to tag first | Notes |
| --- | --- | --- | --- | --- |
| GOV-*, P-*, NR-* | Product/spec governance | `SPEC.md` | (manual review) | Philosophy + non-requirements; no runtime hooks. |
| LAYOUT-*, FR-MD-*, EXT-*, TYPE-*, REL-*, VAL-* | Dataset validity + parsing | `packages/dataset/src/validate/validateDatasetSnapshot.ts`, `packages/dataset/src/parse/datasetObjects.ts`, `packages/dataset/src/parse/markdownRecord.ts`, `packages/dataset/src/parse/wikiRefs.ts`, `packages/dataset/src/model/ids.ts` | `packages/dataset/src/__tests__/spec/*.integration.test.ts`, `packages/dataset/src/parse/__tests__/markdownRecord.unit.test.ts`, `packages/dataset/src/parse/__tests__/wikiRefs.unit.test.ts` | Keep dataset rules aligned with SPEC; web should read via runtime. |
